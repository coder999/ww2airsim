# Plan 6b — Strike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The pilot carries bombs and rockets from the title screen, releases them with V and E, and can sink an anchored merchant ship and raze Dulag's hangars and tower — the second slice of Plan 6 (master spec §5 "Guns"/"Damage", §15 row 6).

**Architecture:** Stores (bombs, rockets) are counted per aircraft in `AircraftCombat` (the same place ammo already lives) and their remaining mass/drag are baked into a derived `AircraftSpec` by a new `storesSpec()`, exactly as `damagedSpec()` already bakes damage in — `massKg` and the flight model's drag sum need only two small, bit-identical-when-empty reads added. Release is a one-shot edge (`Controls.dropBomb`/`fireRockets`), matching the existing `throttleCut` pattern, not the held `fire` trigger. Ordnance extends the existing `Projectile`/`flyProjectile`/nearest-contact machinery in `src/sim/weapons/combat.ts` with a `kind` field, gravity+drag for bombs and a closed-form burn for rockets. Buildings become static content (`Airfield.buildings`) and a new `World.structures` (position/geometry only, never stepped); **all mutable combat state — aircraft damage, ship damage, structure damage — stays inside `CombatState`, keyed by entity id**, matching the existing architecture where `AircraftEntity` itself never carries `Damage` (a deliberate departure from the design spec's literal wording that `ShipEntity` "gains" a `damage` field; see Task 5's ruling).

**Tech Stack:** TypeScript, vitest (Node, Tier 1), Playwright against the Windows reference GPU (Tier 2), three.js WebGPU/TSL, zod for content schemas.

**Spec:** `docs/superpowers/specs/2026-09-20-strike-design.md`. This plan resolves three places where the spec's prose and the current repo disagree; each is called out as a **Ruling** where it first matters (buildings/huts in Task 2, where store mass/drag lives in Task 3, where ship/structure damage lives in Task 5) rather than amending the spec file, because — unlike Plan 8's bearing correction — these are architecture choices the design didn't have to get right, not sourced facts it got wrong.

### Task 3: Stores content, mass and drag — bit-identical when empty

**Ruling:** the spec puts `stores` on `AircraftCombat` (per-aircraft mutable count) but doesn't say how the flight model reads it. `SimContext` explicitly documents "a field when they have a consumer for it" as its ONLY extension rule, and stores are per-aircraft while `SimContext` is otherwise world-global (`wind`, `decks`) or absent by design. The existing precedent for per-aircraft combat state reaching the pure flight model is `damagedSpec(spec, damage)`, called at the exact site `stepper(damagedSpec(entity.spec, damage), entity.state, assisted.controls, ctx)` in `stepAircraftEntity` (`src/sim/loop.ts:597`, confirmed 2026-09-22). Stores follow the same idiom: a new `storesSpec(spec, stores)` bakes remaining store mass into `spec.mass.emptyKg` and remaining store drag area into a new `spec.storesLoad.dragAreaM2` field, so `massKg` needs **zero** changes and the drag sum needs exactly one addend.

**Files:**
- Modify: `content/aircraft/f6f-hellcat.json`
- Create: `src/sim/weapons/stores.ts`
- Modify: `src/sim/flight/schema.ts` (add `stores` to `AircraftSpec`, `storesLoad` derived field)
- Modify: `src/sim/flight/model.ts:327-330` (drag sum)
- Modify: `src/sim/loop.ts:597` (chain `storesSpec`)
- Test: `tests/sim/stores.test.ts` (create)

**Interfaces:**
- Produces:
  ```ts

import type { AircraftSpec } from '../flight/schema.js'

export type StoresState = { readonly bombs: number; readonly rockets: number }
export const emptyStores: StoresState = { bombs: 0, rockets: 0 }

export type Loadout = 'clean' | 'bombs' | 'rockets' | 'both'

/** Counts from the title screen's choice (spec §2.4: loadout is NOT scenario
 *  content). A spec with no `stores` block only ever returns `emptyStores`. */
export function storesFromLoadout(spec: AircraftSpec, loadout: Loadout): StoresState {
  const s = spec.stores
  if (s === undefined || loadout === 'clean') return emptyStores
  return {
    bombs: loadout === 'bombs' || loadout === 'both' ? s.racks.length : 0,
    rockets: loadout === 'rockets' || loadout === 'both' ? s.rails.length : 0,
  }
}

/**
 * Bakes the REMAINING store mass and drag area into a derived spec, exactly
 * as `damagedSpec` bakes damage in (Plan 6b, following that precedent so
 * `massKg` and the drag sum need no new parameter). Returns the SAME OBJECT
 * when there is nothing carried, so the calm path is bit-identical -- the
 * `=== f6f` identity the tests in `stores.test.ts` pin.
 */
export function storesSpec(spec: AircraftSpec, stores: StoresState): AircraftSpec {
  if (stores.bombs === 0 && stores.rockets === 0) return spec
  const s = spec.stores
  if (s === undefined) return spec
  const bombType = s.types[s.racks[0]!.store]!
  const rocketType = s.types[s.rails[0]!.store]!
  const massKgLoad = stores.bombs * bombType.massKg + stores.rockets * rocketType.massKg
  const dragAreaM2Load = stores.bombs * bombType.dragAreaM2 + stores.rockets * rocketType.dragAreaM2
  return {
    ...spec,
    mass: { ...spec.mass, emptyKg: spec.mass.emptyKg + massKgLoad },
    storesLoad: { massKg: massKgLoad, dragAreaM2: dragAreaM2Load },
  }
}
```

```ts
import { localToWorld, runwayHeadingRad, type Airfield } from '../world/airfields.js'

/** A strike target derived from airfield content, never stepped (spec §3.5:
 *  "no motion, no aging"). Built once at world creation from EVERY airfield's
 *  `buildings` -- friendly and enemy both, because only content (`enemyAirfields`
 *  on the scenario) decides what is worth bombing, not this list. */
export type StructureEntity = {
  readonly id: string
  readonly airfield: string
  readonly kind: 'hangar' | 'tower'
  readonly position: Vec3
  readonly headingRad: number
  readonly halfSize: { readonly x: number; readonly y: number; readonly z: number }

}

 *  taller than this, and the box test only needs an upper bound. */
const BUILDING_HEIGHT_M = 10

export function buildStructures(airfields: readonly Airfield[]): readonly StructureEntity[] {
  const out: StructureEntity[] = []
  for (const a of airfields) {
    const heading = runwayHeadingRad(a)
    for (const b of a.buildings) {
      const world = localToWorld(a, b.x, b.z)
      out.push({
        id: b.id,
        airfield: a.id,
        kind: b.kind,
        position: v3(world.x, BUILDING_HEIGHT_M / 2, world.z),
        headingRad: heading,
        halfSize: { x: b.widthM / 2, y: BUILDING_HEIGHT_M / 2, z: b.lengthM / 2 },
        hp: b.hp,
      })
    }
  }
  return out
}

  readonly hp: number
  readonly destroyedTick: number | null
  readonly attacker: string | null
}
```
