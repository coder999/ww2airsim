## Mark's decisions for this plan (2026-09-26)

1. **Relaunch after a trap: automatic respot.** Today a trap never lets go. `arrested` in `src/sim/flight/model.ts` stays true for as long as the wheels are on the deck, whatever the hook does. Even with throttle, 17 m/s² of deck-relative speed is taken off every tick, so after trap 1 a pilot could never take off again. After an intermediate trap, the sim puts the player back on his start spot, like a deck crew would. Mark chose this over two alternatives: "hook up releases the wire", and a single-trap Deck Quals.
2. **"No wave-offs" counts passes that miss.** A pass opens when the player enters the Paddles window (gear and hook down, astern, inside the cone and range). It resolves as trapped if a landing on that ship follows. It resolves as missed if the player leaves the window and no landing comes within `PASS_RESOLVE_S`. This adds one objective kind, `approaches`, to spec §2.1's vocabulary, and Mark accepted that addition.
3. Viewing: final product only, unattended.
4. Work runs on `worktree-missions-track`, after M2.

## Rulings this plan makes

Each ruling is an engineering choice inside the approved spec, with what it costs if it is wrong.

- **M3-R1. The respot is opt-in content: `land.respot: true`.** It needs the player to start `parkedAt` the same ship, and `checkMission` makes that a parse error otherwise. The spot is the player's own start spot. The alternative, a respot implied by any multi-count carrier `land`, would change behavior nobody asked for. Cost if wrong: one boolean in one file.
- **M3-R2. The respot fires `RESPOT_DELAY_S = 3` seconds after the intermediate landing is logged**, and only if the player is still alive. A landing is logged at rest, so the pilot sees the trap stop, reads "Trap 1 of 3", and then the deck crew moves him. The respot sets `previous = state`, as a spawn does, so the renderer never interpolates across the jump. It keeps fuel and flap position; the stores are combat state and are untouched. Cost if wrong: a tuning constant.
- **M3-R3. The respot does not raise the hook.** Controls belong to input, and the frame rebuilds them every frame from the player's toggles, so the sim cannot hold the hook up. The respot's radio line says so: `Flight deck: respotted for launch. Raise your hook before you roll.` Rolling out with the hook down re-arrests in the trap zone, which is what a real pendant would do (Measured). Cost if wrong: a pilot who ignores the radio sits on the wire, raises the hook, and rolls from there. That takeoff flies too (Measured, the −29 row).
- **M3-R4. A pass resolves on the first of two events.** It resolves as trapped on a landing at the pass's ship while the pass is open or pending. It resolves as missed once `PASS_RESOLVE_S = 15` seconds have passed since the player left the window without re-entering it. A bolter (a touchdown with no arrest and no stop) produces no landing, so it is missed; so is a go-around, and so is raising the gear or hook on short final. The Paddles window is exactly `paddlesCue`'s gate, extracted as `paddlesWindow`, so the pass logic and the LSO can never disagree about what counts as "in the groove". Cost if wrong: a tuning constant, bounded by Task 3's measured exit-to-landing gap.
- **M3-R5. The Deck Quals mission is labeled "Carrier Qualification"** in the picker. Its id is `deck-quals-mission`, per spec §4.1, and GAMEPLAY.md's mission list calls it Deck Quals. The range keeps "Deck Quals", because existing e2e selectors match by substring and must keep resolving to one radio. The briefing and GAMEPLAY.md say "Deck Quals (Carrier Qualification)". Cost if wrong: a label edit plus a selector sweep.
- **M3-R6. Every M3 mission has a primary `land` objective that names its home base**, with `after` its last attack objective. The badge rule alone (spec §2.4) would accept any named-base landing, including an **axis** field such as Dulag, while it is hostile. The explicit `land` objective makes that "Recover: incomplete". Cost if wrong: none; the objective line reads RECOVER at the right moment.
- **M3-R7. The convoy escort is `kagero-dd` if `content/ships/kagero-dd.json` is on the branch when Task 6 starts** (R2 merged); otherwise it is `fletcher-dd`, a US destroyer, as a labeled stand-in. The stand-in is noted in the briefing's situation text and in the handoff, and the swap is a one-word content edit, the same pattern spec §4 gives for the Zero. Cost if wrong: a US destroyer escorting a Japanese convoy until R2 merges.
- **M3-R8. The Dulag defenders are `f6f-hellcat` stand-ins** (spec §4). The airframe the Library draws is Lane B's business.
- **M3-R9. Tuning notes live in the tests, not in content.** Scenario JSON has no comment field, and the schema is `.strict()`. Spec §4 asks for "a dated comment" on every tuned value (radii, times, counts, spawn points). It goes on the test that pins the value, in `tests/sim/mission/missions/<id>.test.ts`.
- **M3-R10. Objective targets must be on the right side, checked when the world is built:**
  - every `destroy` target and `deny` hostile must be on the side opposite the player;
  - every `protect` target must be on the player's side.

  This closes the friendly-fire handoff's item 8. `Taggable` gains `side`: aircraft and ships through `sideOf`, and structures through `airfieldSideOf` with the scenario's `airfieldSides`. Cost if wrong: an intentionally odd mission, such as "sink the captured hulk", would need a side override in content.
- **M3-R11. One `approaches` objective per mission, at a ship with `paddles`.** The pass tracker is one piece of per-mission state, and a ship without `paddles` has no window. Both are load errors.

  /** Mark, 2026-09-26: after an intermediate trap the deck crew respots the
   *  player on his start spot, because a trap never releases
   *  (`arrested` latches while the wheels are on the deck, model.ts). */
  export type RespotOrder = { readonly ship: string; readonly spot: { readonly x: number; readonly z: number } }
  /** Seconds from the landing (logged at rest) to the respot (M3-R2). */
  export const RESPOT_DELAY_S = 3
  export const RESPOT_MESSAGE = 'Flight deck: respotted for launch. Raise your hook before you roll.'

  /** An airplane at rest on `spot` of `deck`, facing the bow, gear down,
   *  moving with the deck. `buildAircraft`'s ship-parked start, moved here
   *  so the respot and the start are one construction. */
  export function stateOnDeck(
    spec: AircraftSpec, deck: Deck, spot: { readonly x: number; readonly z: number },
    keep: Partial<Pick<AircraftState, 'fuelKg' | 'flapFraction' | 'tick'>> = {},
  ): AircraftState {
    const at = deckWorld(deck, spot.x, spot.z)
    return createState({
      position: v3(at.x, deck.center.y + spec.gear.heightM, at.z),
      velocity: groundUnder(null, [deck], at.x, at.z)!.velocity,
      attitude: qFromAxisAngle(v3(0, 1, 0), Math.PI / 2 - deck.headingRad),
      gearFraction: 1,
      ...keep,
    })
  }

  export function respotPlayer<M>(
    aircraft: readonly AircraftEntity<M>[], player: EntityId, ships: readonly ShipEntity[], order: RespotOrder, tick: number,
  ): AircraftEntity<M>[] {
    const ship = ships.find((s) => s.id === order.ship)
    const deck = ship === undefined ? null : deckOf(ship)
    if (deck === null) throw new Error(`respot: ship "${order.ship}" has no flight deck in this world`)
    return aircraft.map((a) => {
      if (a.id !== player) return a
      const state = stateOnDeck(a.spec, deck, order.spot, { fuelKg: a.state.fuelKg, flapFraction: a.state.flapFraction, tick })
      return { ...a, state, previous: state }
    })
  }

  import { ticksFor } from './state.js'

  /** One approach to a deck (Mark, 2026-09-26: "no wave-offs" counts passes
   *  that miss). Open while the player is in the Paddles window; pending
   *  once he leaves it; resolved by a landing on that ship, or by
   *  PASS_RESOLVE_S without one. */
  export type PassTracking = { readonly open: boolean; readonly exitTick: number | null }
  export const NO_PASS: PassTracking = Object.freeze({ open: false, exitTick: null })
  /** Measured 2026-09-26 (M3 Task 3 Step 1): a clean trap's window exit comes
   *  <GAP> s before its landing report. Twice that bounds this from below. */
  export const PASS_RESOLVE_S = 15
  export const WAVE_OFF_MESSAGE = 'Paddles: wave-off — go around.'
  export type PassEvent = 'trapped' | 'missed' | null

  export function nextPass(p: PassTracking, inWindow: boolean, landedHere: boolean, tick: number): { readonly pass: PassTracking; readonly event: PassEvent } {
    const live = p.open || p.exitTick !== null
    if (landedHere && live) return { pass: NO_PASS, event: 'trapped' }
    if (inWindow) return p.open && p.exitTick === null ? { pass: p, event: null } : { pass: { open: true, exitTick: null }, event: null }
    if (p.open) return { pass: { open: false, exitTick: tick }, event: null }
    if (p.exitTick !== null && tick - p.exitTick >= ticksFor(PASS_RESOLVE_S)) return { pass: NO_PASS, event: 'missed' }
    return { pass: p, event: null }
  }
