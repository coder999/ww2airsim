# Plan 5 — The ocean: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put real water over real Leyte Gulf — a cascaded Tessendorf FFT sea
driven by a Beaufort wind setting, attenuated and coloured by GEBCO
bathymetry, and sunk by the same Earth curvature the terrain uses, which is
what makes the coast read as a beach instead of a wall.

**Architecture:** An offline Node pipeline pulls a GEBCO_2026 subset over
OPeNDAP and resamples it onto one 513² depth field on the terrain's own grid.
At runtime three spectrum cascades are evolved and inverse-transformed by raw
WGSL compute kernels into displacement, normal and folding targets, which
drive a camera-centred ring surface extending to 400 km. Everything
mathematical — the spectrum, the transform, the sink, the samplers — exists
first as pure TypeScript that runs headlessly in Node, and the GPU is checked
against it.

**Tech Stack:** TypeScript strict, Node 22, vitest, Three.js WebGPURenderer
with TSL for the material graph and `wgslFn` for the compute kernels, Zod for
the header schema, Playwright for Tier 2. No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-15-ocean-design.md`

```ts
// src/render/horizon.ts
import { mul, type ShaderNodeObject } from 'three/tsl'
import type { Node } from 'three/webgpu'
import { EARTH_RADIUS_M } from '../sim/world/projection.js'

/**
 * How far the Earth's surface falls below the tangent plane at a given
 * horizontal distance: the `d^2/2R` of master spec §4.
 *
 * **This is the only place that expression may live**, and
 * `tests/architecture/boundary.test.ts` asserts it. The reason is not tidiness.
 * Plan 4 applied the sink to the terrain and not to the water, so the flat sea
 * at `y = 0` occluded every coast lower than the sink at its own distance --
 * 80.4 m at 32 km -- and the beach was invisible. That was ruled "not a bug,
 * it is the ocean's to fix" on 2026-09-14. A second copy of this expression is
 * how that defect comes back: one surface gets an edit and the other does not,
 * and the symptom is geography rather than a stack trace.
 *
 * The same hazard is why the Plan 4 hand-off insists a vertical exaggeration
 * would be "one number, two call sites, and a test that they are the same
 * number".
 *
 * Even in `distanceM` because distance is unsigned in meaning; taking a signed
 * value and squaring it is the caller-friendly shape and cannot surprise.
 */
export function horizonSinkM(distanceM: number): number {
  return (distanceM * distanceM) / (2 * EARTH_RADIUS_M)
}

/**
 * The distance to the true horizon from a given eye height, the exact inverse
 * of `horizonSinkM`.
 *
 * This is what sets `OCEAN_EXTENT_M`, and it is why the ocean cannot simply
 * inherit the terrain's 100 km draw distance: at 3,000 m the horizon is
 * 195.5 km away, so a 100 km surface would put the edge of the world in frame
 * at the altitude Plan 4's own reference screenshots were taken from.
 */
export function horizonDistanceM(eyeHeightM: number): number {
  return Math.sqrt(2 * EARTH_RADIUS_M * eyeHeightM)
}

/**
 * How far the ocean surface extends from the camera, metres.
 *
 * 400 km, from `horizonDistanceM(11_370) = 380.6 km` -- the horizon at the
 * F6F's service ceiling of ~37,300 ft -- rounded up.
 *
 * The service ceiling is NOT currently in `content/aircraft/f6f-hellcat.json`
 * (the schema has `diveSpeedMps` and no ceiling), so it is a historical figure
 * and is cited in `ASSETS.md` rather than asserted here. Nothing depends on it
 * being exact: it sets a draw distance and the rounding absorbs a wide error.
 */
export const OCEAN_EXTENT_M = 400_000

/**
 * `horizonSinkM` as a TSL node, for a material's `positionNode`.
 *
 * Kept in this module beside the scalar rather than in a GPU-only one so that
 * the boundary test above has a single file to point at. `three/tsl` imports
 * cleanly under plain Node -- verified 2026-09-15, 682 exports -- so this
 * module stays importable by a headless test.
 */
export function horizonSinkNode(distanceM: ShaderNodeObject<Node>): ShaderNodeObject<Node> {
  return mul(distanceM, distanceM).div(2 * EARTH_RADIUS_M)
}
```

### Task 2: Beaufort, wind, and the spectrum

**Implementation corrections (2026-09-15):** The checked-in modules/tests are
now authoritative over the illustrative snippets below. The peak coefficient
uses `0.877 / 1.026` for U10 (Stewart §16.4); the integral is
`alpha * g² / (5 * omegaP⁴)`, since the exponent contains 1.25. The previous
closed form omitted that factor. The integration test covers forces 1–12
through 200 rad/s with 0.005% relative tolerance; the old 20 rad/s cutoff
missed 1.9% of force 1's height. This stricter check catches the 0.0082 alpha
mutation too. The independently sourced Beaufort comparison retains its

- [ ] **Step 3: Write `beaufort.ts`, with the table cited**

**Before writing the numbers, find and read a citable source for the WMO
Beaufort scale** — mean 10 m wind speed in m/s and probable significant wave
height in the open sea. Put the source's name and the retrieval date in the

```ts
// src/render/ocean/beaufort.ts
/**
 * The Beaufort scale, as a table.
 *
 * Source: <NAME THE CITED SOURCE, retrieved YYYY-MM-DD>. Columns are the mean
 * wind speed at 10 m in m/s and the probable significant wave height in the
 * open sea in metres.
 *
 * The wave-height column is NOT what the renderer draws -- the spectrum in
 * `spectrum.ts` produces that. It is here as an independent cross-check on the
 * spectrum's parameterisation (see that module's test), which is the only way
 * to catch a spectrum that is internally consistent and physically wrong.
 */
const TABLE: readonly (readonly [windMps: number, waveM: number])[] = [
  [0.0, 0.0],   [1.0, 0.1],   [2.5, 0.2],   [4.4, 0.6],
  [6.7, 1.0],   [9.4, 2.0],   [12.3, 3.0],  [15.5, 4.0],
  [19.0, 5.5],  [22.6, 7.0],  [26.5, 9.0],  [30.6, 11.5],
  [34.0, 14.0],
]

export const BEAUFORT_MIN = 0
export const BEAUFORT_MAX = 12

function row(beaufort: number): readonly [number, number] {
  if (!Number.isFinite(beaufort)) throw new Error(`beaufort: ${beaufort} is not a finite number`)
  if (!Number.isInteger(beaufort)) throw new Error(`beaufort: ${beaufort} is not an integer`)
  if (beaufort < BEAUFORT_MIN || beaufort > BEAUFORT_MAX) {
    throw new Error(`beaufort: ${beaufort} is outside the scale, which runs 0 and 12 inclusive`)
  }
  return TABLE[beaufort]!
}

/** Mean wind speed at 10 m for a Beaufort force, m/s. */
export function windSpeedMps(beaufort: number): number {
  return row(beaufort)[0]
}

/** Probable significant wave height in the open sea for a Beaufort force, m.
 *  A cross-check on the spectrum, never an input to it. */
export function wmoWaveHeightM(beaufort: number): number {
  return row(beaufort)[1]
}
```

- [ ] **Step 5: Write the spectrum test — two assertions with two different jobs**

This is the task's substance. The first assertion checks the **code** against
closed-form physics. The second checks the **parameterisation** against an
independent table, and is deliberately scoped, because Pierson–Moskowitz
describes a fully developed sea and the WMO column does not.

```ts
// tests/render/ocean/spectrum.test.ts
import { describe, expect, it } from 'vitest'
import { windSpeedMps, wmoWaveHeightM } from '../../../src/render/ocean/beaufort.js'
import {
  angularFrequency,
  significantWaveHeightM,
  spectralMomentZero,
} from '../../../src/render/ocean/spectrum.js'

const G = 9.81

describe('the dispersion relation', () => {
  it('is the deep-water one, omega^2 = g k', () => {
    for (const k of [0.01, 0.1, 1, 10]) {
      expect(angularFrequency(k) ** 2).toBeCloseTo(G * k, 9)
    }
  })

  it('gives a 100 m swell a period of about 8 seconds', () => {
    // Textbook deep-water check: T = sqrt(2 pi L / g).
    const k = (2 * Math.PI) / 100
    const periodS = (2 * Math.PI) / angularFrequency(k)
    expect(periodS).toBeCloseTo(8.0, 1)
  })
})

describe('significant wave height from the discretised spectrum', () => {
  // THE assertion about the code. Hs = 4 sqrt(m0), and for Pierson-Moskowitz
  // m0 has a closed form: alpha g^2 / (4 omega_p^4). If the numerical
  // integration or the normalisation is wrong, these diverge. This is the
  // classic Tessendorf error and nothing else in the pipeline catches it --
  // a mis-normalised spectrum produces water that simply looks like water.
  const ALPHA = 0.0081
  const closedFormHs = (u: number): number => {
    const omegaP = (0.877 * G) / u
    const m0 = (ALPHA * G * G) / (4 * omegaP ** 4)
    return 4 * Math.sqrt(m0)
  }

  it.each([3, 4, 5, 6, 7])('matches the closed form at Beaufort %i', (b) => {
    const u = windSpeedMps(b)
    // A wide, finely-spaced band: the tail of omega^-5 carries little energy
    // but truncating it too early biases m0 low.
    const omegas = Array.from({ length: 4000 }, (_, i) => 0.05 + i * 0.005)
```

```ts
// src/render/ocean/spectrum.ts
/**
 * The wave spectrum: how much energy the sea carries at each frequency, and
 * the relation between a wave's length and how fast it oscillates.
 *
 * Pierson-Moskowitz, which is JONSWAP with a peak-enhancement factor of 1.
 * Chosen over full JONSWAP because JONSWAP's extra parameter describes
 * fetch-limited seas and this world is one 200 km box with one wind setting:
 * the parameter would have no honest value to take. `spectrum.test.ts` records
 * where PM parts company with the WMO table and why that is expected rather
 * than a defect.
 */

/** Standard gravity, m/s^2. The same value the flight model uses. */
const G = 9.81

/** Phillips' equilibrium-range constant, dimensionless. */
const ALPHA = 0.0081

/** Peak frequency coefficient: omega_p = PEAK_COEFF * g / U10. */
const PEAK_COEFF = 0.877

/**
 * The deep-water dispersion relation, `omega^2 = g k`.
 *
 * Deep water is the right approximation everywhere the player flies: the
 * shallow-water correction matters below about half a wavelength of depth, and
 * the depth field says Leyte Gulf is 100 m and more over essentially all of the
 * flyable area. Shoaling is handled as an amplitude attenuation against depth
 * in the material (design §6), not by changing this relation -- which keeps the
 * FFT's frequency grid independent of position, and it has to be, because one
 * transform covers the whole patch.
 */
export function angularFrequency(waveNumberK: number): number {
  return Math.sqrt(G * Math.abs(waveNumberK))
}

/** The Pierson-Moskowitz energy density at one angular frequency, m^2 s. */
export function pmSpectrum(omega: number, windSpeedMps: number): number {
  if (omega <= 0 || windSpeedMps <= 0) return 0
  const omegaP = (PEAK_COEFF * G) / windSpeedMps
  return ((ALPHA * G * G) / omega ** 5) * Math.exp(-1.25 * (omegaP / omega) ** 4)
}

/**
 * The zeroth spectral moment -- the variance of the surface elevation --
 * integrated over the given frequency samples by the trapezium rule.
 *
 * `omegas` must be ascending. Passed in rather than chosen here so the test
 * can state the band it integrates over: `m0` is sensitive to truncating the
 * `omega^-5` tail, and a band chosen silently inside this function would make
 * a wrong answer look like a modelling choice.
 */
export function spectralMomentZero(windSpeedMps: number, omegas: readonly number[]): number {
  let m0 = 0
  for (let i = 1; i < omegas.length; i++) {
    const a = omegas[i - 1]!
    const b = omegas[i]!
    m0 += ((pmSpectrum(a, windSpeedMps) + pmSpectrum(b, windSpeedMps)) / 2) * (b - a)
  }
  return m0
}

/** Significant wave height from the variance: the standard `Hs = 4 sqrt(m0)`. */
export function significantWaveHeightM(m0: number): number {
  return 4 * Math.sqrt(m0)
}
```

### Task 3: The reference FFT, which is the oracle for everything on the GPU

**Implementation corrections (2026-09-15):** These butterfly tables are
radix-2 decimation-in-time and require a bit-reversal permutation; they are
not Stockham autosort tables. The GPU implementation must honor this contract.
Rows-first and columns-first are equivalent separable transforms, so swapping
pass order must not fail. The additional direct 2-D DFT fixture instead catches
an actual output transpose. The reference's unshifted spectrum layout, random
draw order, Hermitian pairing, and amplitude normalization are documented in
`src/render/ocean/reference.ts`; GPU integration must preserve them. The current
reference describes a full isotropic patch; cascade band partitioning and
wind direction remain integration work, not claimed completed here.

**Files:**
- Create: `src/render/ocean/butterfly.ts`, `src/render/ocean/fft.ts`,
  `src/render/ocean/reference.ts`

**Interfaces:**
- Produces, from `butterfly.ts`:
  - `type Pair = { readonly a: number; readonly b: number; readonly twiddleIndex: number }`
  - `type Stage = { readonly span: number; readonly pairs: readonly Pair[] }`

- Produces, from `fft.ts`:

```ts
// src/render/ocean/butterfly.ts
export type Pair = { readonly a: number; readonly b: number; readonly twiddleIndex: number }
export type Stage = { readonly span: number; readonly pairs: readonly Pair[] }

/**
 * The index tables a radix-2 FFT walks: one `Stage` per doubling, each with
 * `n/2` disjoint index pairs and the twiddle each pair multiplies by.
 *
 * Separated from the arithmetic so that `wgsl.ts` (Task 8) generates the GPU
 * kernel from the SAME tables the reference walks. Two transforms that agree
 * about arithmetic but disagree about indexing produce a field that still
 * looks exactly like waves, which is why this is a module and not a loop.
 */
export function butterflyStages(n: number): readonly Stage[] {
  if (n < 2 || !Number.isInteger(Math.log2(n))) {
    throw new Error(`fft: ${n} is not a power of two`)
  }
  const stages: Stage[] = []
  for (let span = 1; span < n; span *= 2) {
    const pairs: Pair[] = []
    for (let start = 0; start < n; start += span * 2) {
      for (let k = 0; k < span; k++) {
        pairs.push({ a: start + k, b: start + k + span, twiddleIndex: (k * (n / (span * 2))) % n })
      }
    }
    stages.push({ span, pairs })
  }
  return stages
}
```

`fft.ts` walks them and does the arithmetic, plus the naive DFT, plus the
re-export named in the Interfaces block above. Both modules are pure, both take
and return plain typed arrays, and neither knows what a wave is.

Note that `inverseFft2d` handles the 1-D case the DFT comparison uses by
transforming a single row — document that entry point, because the test relies
on it and a reader will otherwise wonder why a 2-D function is called with
`n × 1` data.

Document in `fft.ts`'s header that this implementation exists to be the
**oracle**, not for speed — the browser never calls it in a frame — and that
Tier 2 reads the GPU's displacement target back and compares against it
(Task 11). That is what stops a future reader deleting it as dead weight when
they notice the GPU does the real work.

```ts
import { OCEAN_TIERS, tierForFrameTimeMs } from '../../../src/render/ocean/tiers.js'

describe('the ocean quality tiers', () => {
  it('degrades monotonically in both knobs', () => {
    for (let i = 1; i < OCEAN_TIERS.length; i++) {
```

```ts
// tests/e2e/ocean.spec.ts — the assertion this whole plan is built to permit
test('the GPU FFT agrees with the Node reference FFT', async ({ page }) => {
  await page.goto('/?beaufort=4&oceanTime=0')
  await waitForOcean(page)

  const gpu = await page.evaluate(() => window.__ww2.oceanDisplacementSample(0))
  const reference = referenceDisplacement({ beaufort: 4, timeS: 0, cascade: 0 })

  // Not exact: the GPU is fp32 and the reference is fp64, and the spectrum
  // is seeded from the same pseudo-random sequence on both sides -- which is
  // itself a thing to assert, because a different seed produces a different
  // but equally plausible sea.
  expect(rmsError(gpu, reference)).toBeLessThan(TOLERANCE)
})
```

`referenceDisplacement` already exists — Task 3 built and tested it, seeded

fp32-versus-fp64 difference you actually measure, and state that basis in a
comment — a tolerance chosen to make the test pass is the one thing that would
make this whole assertion theatre.

**If the GPU and the reference turn out not to share a seed after all, this
test is worth nothing and the task is not done** — say so rather than
weakening it into a statistical shape check.
