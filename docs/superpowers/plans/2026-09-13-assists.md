# Plan 3 — Input assists: implementation plan

Design: `docs/superpowers/specs/2026-09-13-assists-design.md`, approved
2026-09-13 with four open questions resolved by me and marked as such there.

## Global constraints

Inherited from Plans 1 and 2, unchanged:

- TypeScript strict. `npm run verify` (typecheck, lint with `--max-warnings 0`,
  depcruise, vitest) must exit 0 before every commit.
- `sim/` may not import `render/`, `input/`, rendering libraries, or Node core,
  and may not touch browser globals. `assists/` is a new directory and inherits
  the same rules: it is deterministic arithmetic and nothing else.
- **No tuning constant may be invented silently.** Every one lands in aircraft
  content with a stated basis, or in code with a comment saying what it was
  measured against. This is the rule the whole project keeps re-learning.
- The golden trajectory must pass UNREGENERATED. An assist sits outside `sim/`
  and the golden is recorded through `step`, so nothing here may move it. If it
  moves, an assist has leaked into the simulation and the task is wrong.
- Every test must be proven to fail with the thing it guards removed. "The
  assist is on and the number looks good" is not evidence the assist did it.

## Starting state

Plan 2 merged at `b5b717a`. 369 tests in 31 files. `advance(world,
elapsedSeconds, stepper)` runs 0..5 fixed steps per frame and already takes its
stepper as an argument. `World` carries `spec`, `aircraft`, `previous`,
`controls` and `accumulatorSeconds`. Controls are ramped per frame in
`nextFrameState`, which is open item 5 and NOT fixed here.

## File structure

```
src/assists/
  index.ts        applyAssists(state, spec, raw, dt, enabled) -> Controls
  autoRudder.ts   sideslip -> yaw command
  stallLimiter.ts bounds the pitch command by alpha
  altitudeHold.ts holds the flight path, stick centred
  settings.ts     AssistSettings, the four flags, all default on
tests/assists/    one file per assist, plus a composition test
```

### Task 1: The seam, with no assists in it

Add `src/assists/index.ts` exporting `applyAssists`, initially the identity
function, and `AssistSettings` with every flag defaulting on. Call it from
`advance` once per tick, before `stepper`.

Proves the wiring in isolation, so a later behavioural failure cannot be
ambiguous between "the assist is wrong" and "the assist never ran".

- Test: `advance` calls `applyAssists` exactly once per STEP, not once per
  frame. Fails if it is hoisted out of the step loop.
- Test: with the identity assist, the golden trajectory is unchanged.
- Test: depcruise forbids `assists/` importing `render/`. New rule, with a
  negative probe, per the pattern the boundary tests already use.

### Task 2: Auto-rudder coordination

The one Mark asked for. Proportional on sideslip, clamped into `[-1, 1]`, added
to the pilot's own yaw command rather than replacing it, so manual rudder still
works with the assist on.

Gain lives in content beside `weathercockSeconds`, because it is per-aircraft
and because inventing it in code is what the constraint above forbids.

- Test: sideslip after a full-deflection roll is smaller with it ON than OFF, at
  90 / 130 / 180 m/s, in BOTH roll directions. Both directions matter: NACA WR
  L-716 measured 18.5 degrees of aileron yaw in left rolls against 23.5 in
  right, so an asymmetry is expected and a sign error would show in one only.
- Test: it does nothing when sideslip is already zero.
- Test: pilot rudder input is still effective with the assist on.
- Proven: with the assist forced off, the first test fails.

### Task 3: Stall limiter

Bounds the pitch command so alpha stays under `alphaCritRad`.

**Fix open item 8 first, inside this task.** `angleOfAttack` keeps the lateral
component in its denominator, so it over-reports alpha by `1/cos(sideslip)` --
34% at 42 degrees. A limiter built on that clamps early in every slipping turn.
Project alpha into the body x-z plane, and expect the soak's stall figures to
move again; re-baseline them with the measurement, as Plan 2 did.

- Test: full back-stick from level flight never exceeds `alphaCritRad`, at
  several speeds.
- Test: it does not interfere below the limit, so ordinary manoeuvring is
  untouched.
- Test: alpha is now independent of sideslip. Fails against the old formula.

### Task 4: Altitude hold (the assist the spec calls "combat trim")

Named for what it does. Hands-off already holds attitude in a rate-command
model; what drifts is the flight path. Holds the altitude at which the stick
was last centred.

- Test: hands off for 60 seconds holds altitude within a band it currently
  misses by a wide margin.
- Test: it yields instantly to pilot pitch input, and re-captures on release.

### Task 5: Switching, and the diagnostics hook

Keyboard toggles, and each flag exposed on the existing `window.__ww2` hook so
Tier 2 can flip them. No options UI: none exists, and the meta-game is far out
in the master spec's ordering.

- Test: each assist is independently switchable, and the composition test
  asserts the stack applies in a fixed, documented order.

### Task 6: Fly it — MARK'S, and the only step I cannot do

Every task above is verifiable headlessly, which is why they can all be built
before he is free. Whether the aeroplane now feels right is not, and this plan
does not claim it.

Specifically worth his judgement: whether auto-rudder is too strong and has made
it feel on rails, and whether the stall limiter intrudes during hard turns.

## Deliberately not in this plan

- **Rate damping**, which the master spec lists. It is a no-op against a
  rate-command model: control input IS the body rate, so a released stick stops
  rotation within a tick and there is no residual for a damper to act on. See
  the design's resolution (C).
- **Rotational inertia**, the change that would make rate damping meaningful and
  is probably the larger feel improvement of the two. It belongs in `sim/`, it
  moves the golden, and it alters how the aeroplane flies, so it wants Mark at
  the controls. Proposed separately.
- **Weakening the weathercock constant** toward the historical figure. Only safe
  once auto-rudder demonstrably carries the feel. Open item 9.
- **Options UI, persistence, per-aircraft assist tuning, AI use of assists.**
  Later plans, per the master spec's ordering.
