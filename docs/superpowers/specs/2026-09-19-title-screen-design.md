# Title screen — design

2026-09-19. Mark supplied a title image generated with Adobe Firefly and asked
for it as the home splash screen with **New game** and **About project**
options, "to start". This is the first slice of Plan 9 (meta-game, menus)
landing ahead of the rest of that plan; the pilot roster, mission select and
a return-to-title from the debrief stay in Plan 9. Three decisions taken with
Mark on 2026-09-19: the world boots BEHIND the title; About shows a short
blurb, the credits and links; the Tier 2 harness reaches the game by pressing
New game, not by a bypass parameter.

## The asset

`content/art/title.png`, the file as supplied: 1408 x 768, 2,077,706 bytes,
not re-encoded, so its embedded provenance survives -- the same rule as
`content/audio/NOTICE.md`. Recorded in `ASSETS.md` and `content/art/NOTICE.md`
(Adobe Firefly, generated by Mark Tuttle, Adobe Terms of Use). The build test
asserts the file reaches `dist/` at that exact byte count, exactly as the
scenario and audio files are asserted. Drawn with cover fit: a 16:9 viewport
crops a sliver from each side of the 1.83:1 image; nothing of the badge or
the buttons' band is lost at any common aspect. A smaller re-encode is a
later optimization, not part of this slice.

The art carries the words WW2 AIRSIM, so the working title is now the
on-screen name. `<title>` stays `ww2airsim`; the About text says the name is
a working title.

## The screen

`src/render/titleScreen.ts`, split like `debrief.ts` and `paddlesBadge.ts`:
a pure model (`titleModel()` -- the button labels, the About paragraphs, the
credits line from `legend.ts`'s `creditsLine()`, the licence sentence and the
repository URL) the Node suite asserts on, and thin DOM beneath it.

- A fixed full-viewport overlay, `role="dialog"`, `aria-label="Title"`, with
  the image as a cover-fit background and a low-center row of two buttons in
  the debrief's button style: **New game** and **About project**. z-index
  above every badge and the flight-data strip, below nothing.
- **Enter** is New game while the title is up. The title owns that key
  listener; `main.ts`'s keydown listener returns early while the title is
  up, so no game binding fires under the art.
- **About project** opens a second panel inside the overlay: the README's
  opening description (browser WWII Pacific sim, F6F Hellcat over a
  geographically real Leyte Gulf, inspired by *Hellcats Over the Pacific*,
  clean-room, working title), the credits line, "AGPL-3.0-or-later" and a
  link to `https://github.com/coder999/ww2airsim`. One **Close** button.
- `hide()` removes the overlay for good. There is no `show()`: nothing in
  this slice returns to the title, and a method nothing calls is how a stale
  document starts (the debrief's own reasoning).
- A failure screen is never masked by the art: `showFailure` (failure.ts)
  empties `#app` before drawing itself (`root.innerHTML = ''`, read
  2026-09-19), and the overlay is a child of `#app`, so it goes with
  everything else. No wrapper is needed; the title's Enter listener is
  removed by `hide()` and is harmless if it outlives the overlay.

## Boot behind it

The title is created first in `boot()`, before `initRenderer`, so it is on
screen while the adapter, the ocean cascades and the terrain load. Everything
below it proceeds unchanged: the scenario resolves, the frame is built, the
loop starts, terrain arrives and `settleOnTerrain` runs.

While the title is up the frame loop treats it exactly as it treats the open
navigation chart (`chartOpen` in `main.ts`): the frame sees no keys and the
world is held paused, so no simulated time passes and no control ramps.
`window.__ww2.tick()` does not advance. New game hides the overlay, releases
that pause (`withPaused(frame, false)`, as `closeNavigationChart` does) and
calls `audio.resume()` -- a click is the gesture the autoplay policy wants,
which closes the first-visit question `docs/handoff/2026-09-18-plan15-audio.md`
left open. A page that boots with the DEV `?spawnX/Y/Z` override behaves the
same way: airborne, held under the title, released on New game.

Restart from the debrief does NOT return to the title. That button is Plan 9's.

## Acceptance

Tier 1: `titleModel()` names both buttons, contains the credits line, the
licence and the repository URL, and the About text; the build test finds
`content/art/title.png` in `dist/` at 2,077,706 bytes.

Tier 2, reference GPU at 1440p (`tests/e2e/title.spec.ts`): the title dialog
and both buttons are visible on load; after `waitForTerrain`'s poll the tick
is unchanged over one second while the title is up; About opens, shows the
repository link, and closes; New game hides the title, the tick advances,
and `audio().state` is `running`; zero WebGPU validation errors; a screenshot
of the title at 2560 x 1440 is taken and READ. `waitForTerrain` in
`harness.ts` presses New game once terrain has landed, so every existing spec
passes through the shipped title unchanged; the full Tier 2 suite is re-run
to prove it. `npm run verify` exits 0 and a dated handoff records the
measurements.
