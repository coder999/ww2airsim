## Decisions and deviations (Mark may overrule)

1. **Fourteen scenes became two demos (Mark chose this, 2026-10-17; the demos are placeholders he will edit).** The A1-J6 chapter missions are F10; `content/scenarios` has none, so "the first N seconds of the mission's own scenario" cannot be authored for a chapter yet. `demo-opening` is on `escort` (airborne, four B-17s), `demo-victory` on `tutorial` (a cargo ship, Tacloban's strip). The F9 gate becomes framework and demos approved; "all fourteen approved" moves to F10, where each chapter authors its scene in director mode. The scene ids `a1-opening`..`j6-opening`, `a6-victory`, `j6-victory` are what the flow looks up.
2. **No FOV and no roll** (Mark's ruling). Keyframes are position, yaw, pitch, ease. Task 4 shrank accordingly; there is no FOV hook and no FOV-consumer test.
3. **The scenario `scene:` block is dropped.** The scene file already carries `durationS` and the handoff, and the world builder is untouched, so a world with no scene is byte-identical by construction (the golden recordings and the mission suites pass unchanged).
4. **`fx` is renderer-only.** It changes no sim state, so skip ignores it; no renderer consumes it yet. It is collected on `Preroll.emitted`.
5. **A scene plays only on the scenario it names.** The opening is skipped (the flight starts as before) when the launched scenario is not the scene's `world.scenario`, as it is when the scene is missing or invalid.
6. **A victory scene replays the scenario's own fresh start, held under Headquarters**, not the world the final flight ended in.
7. `chapter` in the scene file is validated by shape (`/^[AJ][1-6]$/`), not by `CHAPTER_IDS`: `sim/` cannot import `campaign/` (the boundary test caught the first version).

## Bugs the checks found while building

- The diagnostics hook read `scenePlay` before its `let` ran (TDZ); found by the e2e on the first run.
- The director's callbacks wrote a copy of the session object the frame loop never read, so selecting a key did not move the camera and every capture was the same view; found by looking at the stills. `directorEye` and an e2e now guard it.
- A source-text assertion in `tests/render/bootQuality.test.ts` expected the old recorder-push condition.
