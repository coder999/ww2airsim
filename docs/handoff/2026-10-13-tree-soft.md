## Result and tradeoff

The soft mode removes the dotted coverage mask. Distant crowns start faint and
become solid as they approach; near trees remain fully opaque. Inspected ridge
and flight-endpoint captures show a smoother transition without the stipple.
The original tree shapes, colors, normals, range and ground remain unchanged.

This is a fade, not optical defocus. No blur is applied. Transparent trees can
look ghostly, and their overlapping lobes/instances are not individually sorted.
The far-field tree boundary is still present. Mark accepted the visual result;
this does not establish that all popping is gone.

The renderer submits an additional crown/trunk pair sharing the opaque pair's
instance matrices and colors. Opaque and blended fragments occupy complementary
distance regions. Blended fragments depth-test against the scene but do not
write depth. This protects near-tree occlusion while limiting transparency to
the fade band. Lifecycle tests cover both pairs through movement, altitude and
quality changes. `drawnInstances` counts tree sites rather than duplicate draws.

DEV and production builds default to soft; `treeFade=pixel` and `treeFade=whole`
remain DEV comparison choices. Canopy and horizon-lighting experiments stay
off by default. The shared altitude cull skips all tree draws high above terrain.
The updated experiment plan was emailed successfully as required by AGENTS.md.

## Measurements

Reference Ryzen GPU, exclusive `ryzen-budget` lock, 2560×1440, High/100%, noon,
clouds off. Three measurement windows per trees-on/off state; shader order
reversed at the ridge and visibility order alternated. Typecheck and captures
finished before this run. The preflight GPU check found background video-codec
activity and no unrelated 3D load.

Medians of three per-window statistics, in milliseconds:

| View | Pixel p50 | Soft p50 | Pixel p95 | Soft p95 |
| --- | ---: | ---: | ---: | ---: |
| Low, 1,000 ft | 3.467 | 3.676 | 3.481 | 3.702 |
| Ridge, 6,000 ft | 3.365 | 3.581 | 3.899 | 3.841 |
| High, 13,000 ft | 2.953 | 2.959 | 3.213 | 3.507 |

The soft fade adds approximately **0.21–0.22 ms** to median full-frame GPU time
in the two views with trees, about 6%. This is a real cost for the extra draws.
High altitude submits no tree geometry in either mode, so its timing difference
is background variation, not dissolve work. Tail timing remains variable;
the largest individual-window p95 was 4.314 ms. All three budget capture cases
passed, and all 36 windows had over 100 samples and p95 below 8.33 ms.

## Test reconciliation

**Tests updated:** the existing query test includes all three choices and the
new default. A production-mode test verifies that DEV query overrides cannot
restore whole-tree fading in production. The old all-opaque assertion was
replaced by the explicit opaque/blended depth-state contract; the alphaHash
regression check still covers every tree material. The scenery suite checks that opaque and blended instances
stay aligned across buffer repacking, tier changes and altitude culling. The
existing E2E comparison enrolls the soft shader alongside whole/pixel and
requires visible trees, equal instance counts and no GPU/console errors.
The existing budget capture accepts `TREE_FADE_VARIANTS=pixel,soft`.

**Tests still valid:** original placement/exclusion, pixel coverage/seeds,
canopy opt-in/fallback, terrain and lighting contracts. No tree art or range
assertion was weakened.

Passed: Ryzen typecheck, focused lint, 28 unit tests, three-mode shader E2E and
four ridge/moving capture cases. Budget results are recorded above.
After acceptance: typecheck, focused lint, 29 unit tests (including production
mode), and the production build passed. Vite reported its large-chunk warning.
The shader implementation is unchanged from the measured and accepted version.

**Known gaps:** transparent overlap ordering, other
hardware/resolutions and distant forest representation. This intermediate
checkpoint did not run a full-suite merge gate.
